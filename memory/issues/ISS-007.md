## Symptom

`gh pr create` fails with `GraphQL: GitHub Actions is not permitted to create or approve pull requests (createPullRequest)` for any skill running under `.github/workflows/fleet-runner.yml`.

Branch push succeeds (the token has `contents: write`); only PR creation is denied.

First hit by `suggest-edges` on 2026-06-24 (branch `suggest-edges/2026-06-24`, commit `ddea1e9` pushed but PR unopened — operator notified with manual `pull/new/...` URL).

## Why it happens

`fleet-runner.yml` passes `secrets.GITHUB_TOKEN` to skill steps. The aeon GitHub App / default Actions token isn't allowed to create PRs on this repo. The same wall blocks `fix/workflow-security-audit-2026-06-21` per MEMORY.

`sync-upstream.yml` and `messages.yml` already wire `secrets.GH_GLOBAL` (fine-grained PAT) with a `secrets.GITHUB_TOKEN` fallback. The fix is to copy that pattern into `fleet-runner.yml`.

## Affected paths in fleet-runner.yml

- Line 54: `token: ${{ secrets.GITHUB_TOKEN }}` (checkout)
- Line 105: `GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}`
- Line 288: `GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}` (the one that runs the skill)
- Line 310: `git remote set-url origin https://x-access-token:${{ secrets.GITHUB_TOKEN }}@...`

Replace each with `${{ secrets.GH_GLOBAL || secrets.GITHUB_TOKEN }}` to match `messages.yml`.

## How to apply

This is an operator action — Aeon App lacks `workflows` write (same gate that blocks the existing workflow-audit PR). Both fixes can ship in one PR once a human-signed branch is created.
