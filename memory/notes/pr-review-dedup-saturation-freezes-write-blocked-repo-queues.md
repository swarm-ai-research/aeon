# pr-review's 2-day dup-SHA dedup layer self-reinforces into a full-skip freeze on write-blocked repos — queue turnover becomes exogenous once every open head SHA has already been reviewed

**Why:** across the 89th (09-18 morning), 90th (09-18 evening), and 91st (09-19) pr-review invocations against `swarm-ai-research/swarm`, the open queue held byte-identical at 11 PRs with the same 3-bot + 8-dup-SHA split, giving `eligible=0` on all three cycles — the queue has been frozen since 2026-09-17T~19Z when `#624`/`#623`/`#620` dropped out and no new inflow arrived. The dup-SHA rows are standing verdicts from the 86th/87th cycles at the same `headRefOid`, and per [[aeon-app-no-write-on-swarm-repo]] those verdicts never posted to GitHub because `addPullRequestReview` returns 403, so the state that would nominally advance the dedup window (a landed review + reviewer's response to it) never materializes. This is a distinct failure mode from [[swarm-repo-dependabot-cohort-churns-under-full-skip]] (bot-author churn on same SHAs) — here even human-authored research PRs pin because the SHA is stable and pr-review's own state file `memory/triaged-prs.json` treats "verdict drafted at SHA X" as sufficient dedup evidence regardless of whether the verdict landed remotely.

**How to apply:** treat n≥3 consecutive full-skip cycles on the same write-blocked repo as a class signal, not a coincidence — the dedup window is doing exactly what SKILL.md tells it to do, but on a write-blocked repo that produces a self-reinforcing freeze where only exogenous events (operator click-merge, force-push, new PR open, or SHA rebase) can turn the queue over. Two fixes are viable: (a) gate `memory/triaged-prs.json` writes on a successful post confirmation so unposted verdicts remain eligible for retry on the next run (preferred — surfaces the write-block as ongoing rather than pinning it away), or (b) add a per-repo `pr-review-rules/${owner}__${repo}.md` override that shortens or disables the dup-SHA skip on repos with the aeon-app write-block class marker. Until either lands, three consecutive full-skip cycles on the same repo should trigger a one-line notify (skill currently silent per the "if every PR was skipped, do not notify" contract) — the operator needs the visibility to know the report-only posture is now report-nothing.
