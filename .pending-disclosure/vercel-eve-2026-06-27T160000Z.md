### Notes & caveats

- **`sandbox@3.1.2`** (advisories GHSA-fm4j-4xhm-xpwx and GHSA-gc25-3vc5-2jf9, "sandbox breakout / arbitrary code execution"). The package referenced is the npm name `sandbox` — verify with `pnpm why sandbox` that this is not the legitimate Vercel sandbox utility but an unrelated, abandoned npm package pulled in as a transitive dep. If so, the fix is to find which dep is requiring it and remove or override the resolution. The minimum-release-age policy (2880 minutes / 2 days) won't help here because the package has no published fix.
- **Multiple `undici` versions** (5.28.4, 6.26.0, 7.27.2) coexist in the lockfile because different sub-projects pull different major lines. The single `undici: ">=7.28.0"` override may break consumers pinned to <7. If pnpm refuses to apply across majors, use line-specific overrides instead: `"undici@^5": ">=5.29.0"`, `"undici@^6": ">=6.27.0"`, `"undici@^7": ">=7.28.0"`.
- **`@opentelemetry/core` 2.6.1 vs 2.8.0**: the e2e fixtures all pin this directly at `2.6.1`. Bumping requires editing all 11 fixture manifests *and* refreshing the lockfile. If 2.8.0 introduces minor instability in fixtures, scope to a follow-up.
- **Why `dompurify` matters even though it only reaches mermaid in the docs site**: mermaid renders user-controllable diagram input. If a docs PR ever lands a mermaid diagram authored by an external contributor, the sanitization bypasses are reachable. Cheap defense in depth.
