## Triage

`--severity=ERROR,WARNING` returned zero candidates. Re-ran without the
severity filter (INFO included) — still zero. That's an unusual result for
a 909-file scan, so this section documents the manual spot-checks used to
sanity-check the zero: any of these classes appearing in
security-relevant call paths would have overturned the "clean" verdict.

- **Command injection surface (`spawn`, `exec`, `child_process`).** 25 files
  match; every `spawn` in the compiler routes through
  `packages/compiler/src/process-runner.ts`, which enforces `shell: false`,
  rejects NUL bytes in executable/argv/cwd, validates positive-integer limits,
  builds a fresh minimal-env child, isolates the child in a mode-0700 private
  temp dir, and terminates the whole process tree with SIGTERM→SIGKILL
  escalation on abort. No pattern of user-controlled string interpolation into
  argv.
- **Code-eval sinks (`eval`, `new Function(...)`, template `Function(...)`).**
  One match total, and it's an *anti-string* inside
  `packages/element/test/security.test.ts` — the test suite asserting `eval(`
  does not appear. Zero real eval-family sinks.
- **DOM injection sinks (`innerHTML`, `outerHTML`, `dangerouslySetInnerHTML`,
  `document.write`).** No matches anywhere in TS/JS/MJS source.
- **Worker-message ingress (`onmessage`, `addEventListener('message', ...)`).**
  Two files: `packages/player-web/src/decoder-worker/{host,client}.ts`. The
  host validates every inbound message through `isDecoderWorkerCommand(...)`
  in `packages/player-web/src/decoder-worker/protocol-validation.ts` before
  dispatch, and calls `rejectMalformedCommand(...)` on any non-command
  payload. `readRequestId(...)` treats missing/negative/non-integer request
  IDs as `null`. Well-defined trust boundary.
- **Untrusted-byte parsers.** `packages/format/src/{parser,header,layout}.ts`
  and codec-specific parsers use `DataView`/`Uint8Array` throughout. A
  `checked-integer.ts` helper and per-file `manifest-*-schema.ts` validators
  indicate the parsers reject out-of-range integers and unknown fields
  before use — matches the SECURITY.md line about "strict parser rejection".

No candidate advanced past step 1 of the triage matrix. Not a single "one
sentence describing what the attacker controls" fits any grep hit above.
Nothing behind a feature flag, nothing in production paths, nothing
requiring an unrealistic privilege drop.

## Notes for future runs

Aval is a maintainer-hardened codebase: process runner enforces every
common defense-in-depth pattern, worker protocol is validated at the
transport layer, no eval-family sinks in source. If a future run finds a
regression here it will be a genuinely novel bug, not low-hanging fruit —
worth an extra pass of manual review before triaging clean.
