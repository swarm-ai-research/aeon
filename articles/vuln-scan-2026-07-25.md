### Confirmed findings

**1. GitHub Actions shell injection via unquoted PR-author-controlled context**
- **Severity:** medium (arbitrary code execution on the runner, scoped to a read-only `GITHUB_TOKEN` on `pull_request`-from-fork; escalates to high if the workflow is ever changed to `pull_request_target` or has `permissions:` widened).
- **File/line:** *[redacted — see PVR draft]*
- **Attacker capability:** any fork PR against `main` with a specially-crafted branch name triggers shell interpretation of the branch string inside the workflow's `run:` block.
- **Suggested fix:** move the `${{ github.head_ref }}` value into an `env:` block and reference `$HEAD_REF` from the shell (standard GH Actions hardening pattern).
- **Disclosure channel:** PVR (drafted).
