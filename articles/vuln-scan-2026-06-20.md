## Triage summary

- **47 semgrep candidates → 0 confirmed code vulnerabilities.** Findings break down into known false-positive shapes:
  - `subprocess shell=True` (×3 ERROR): all three sites carry explicit code comments documenting the command source as trusted local config — a chained user-supplied statusLine command (`claude_native_status.py`), a deliberate agent-exposed `Bash` tool intended for the LLM (`client_tools/coding.py`), and a spec-author-supplied credential fetcher running outside the sandbox (`inner/credential_proxy.py`).
  - `subprocess "tainted env"` (×2 ERROR): both sites use `subprocess.Popen` with **list argv** (not shell), and the `env` mapping is built from internal config, not network input.
  - `sqlalchemy.text()` (×3 ERROR): all three uses correctly bind parameters; only a hardcoded constant table name (`_FTS_TABLE = "conversation_items_fts"`) is f-string interpolated.
  - GitHub Actions `run` shell-injection (×1 ERROR): the interpolated values are typed integers (`github.event.issue.number`, `github.event.pull_request.number`, `inputs.pr`).
  - Dockerfile `last-user-is-root` / `missing-user` (×3 ERROR): container hardening, not directly exploitable; the cloudflare Dockerfile is a Worker build container.
  - React `dangerouslySetInnerHTML` (×1 WARNING): in a vendored `ai-elements/` UI component (`schema-display.tsx`) that is **not consumed anywhere inside the repo** and carries an explicit `oxlint-disable-next-line eslint-plugin-react(no-danger)` — library code shipped to downstream consumers, not part of omnigent's runtime.
  - Django `raw-html-format` (×1 WARNING): the interpolated value is `_html.escape(email)` — properly escaped.
  - `dynamic-urllib` (×6 WARNING): every URL is constructed from local IPC config (loopback bridge files, `127.0.0.1` server URLs) or a hardcoded template — no attacker-influenced fetch surface.
  - `logger-credential-disclosure` (×11 WARNING): all sampled sites log non-secret context (server URL only, HTTP status code + provider error body, host/path/method); the rule fires on identifier names in scope, not actual secret values.
  - `insecure-file-permissions` (×10 WARNING): every sampled site sets restrictive modes (`0o600` for credential files, `0o700` for session/agent dirs); rule fires on the call shape regardless of mode value.
  - MD5 (×3 WARNING): all three uses are non-security — Cursor chat-dir interop hash and stable 12-char Gemini tool-call IDs.
  - Kubernetes missing `securityContext` / `allowPrivilegeEscalation` (×3 WARNING): hardening recommendation; not exploitable by itself.
- **0 verified secrets** (filesystem + 200-commit git history).
- **20 vulnerable packages** across 4 lockfiles; after dropping the **test-only** Cargo tree under `tests/codex_parity/sidecar/`, **9 production-impacting CVE clusters** remain in `uv.lock`, `ap-web/package-lock.json`, and `ap-web/electron/package-lock.json`.
