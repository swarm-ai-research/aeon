## Candidates and triage

**Semgrep candidates: 4 (triaged out).**
All four are `github-actions-mutable-action-tag` WARNINGs on `.github/workflows/ci.yml` lines 17/19/31/32 — the workflow pins `actions/checkout@v7`, `astral-sh/setup-uv@v10.2.0`, `actions/setup-node@v7` by tag rather than SHA. On this workflow the risk is bounded: the job references no `secrets.X`, declares no custom `permissions:`, and runs only `uv sync --dev` + `uv run pytest -q` + `npm ci` + `npm run build`. A compromised tag could poison dependency installs on CI runners but cannot exfiltrate anything from this repo. Not filed as a vulnerability per skill rule "requires attacker privileges equal to or greater than the attack yields" and because the repo has no PVR-safe channel. Operator may still want to pin tags; left as a sentence in the dep-bump PR body if they do.

## Confirmed findings

**Code vulnerabilities: 0.** The app's security posture is good for a desktop-grade finance app:
- No `subprocess`, `os.system`, `eval`, `exec`, `pickle.load`, `yaml.load`, or `shell=True` in `backend/app/`.
- Backend binds to default localhost in `start.sh:71` (`uvicorn app.main:app --port "$port" --no-access-log`); CORS allows only `http://localhost:5173` and `http://127.0.0.1:5173`.
- The MCP server (`backend/app/mcp_server.py`) is stdio-only and opens SQLite in `mode=ro`.
- Outbound HTTP is restricted to hardcoded endpoints: ECB fx (`backend/app/fx.py:91`), OpenRouter (`backend/app/advisor.py:34`), yfinance/Morningstar via vendored libs — no attacker-controlled URL path reaches the fetcher.
- SQLAlchemy ORM used throughout; no raw-SQL concatenation surfaced in a grep of `backend/app/`.

**Dependency CVEs: 23 across 6 transitive packages** → one dep-bump PR drafted. Fix is a single `uv lock --upgrade-package …` invocation that touches `backend/uv.lock` only; `pyproject.toml` is unchanged and so is application code.
