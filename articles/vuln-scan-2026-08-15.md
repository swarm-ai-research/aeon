### High-risk surfaces reviewed manually (found clean)
- **OAuth flow** (`apps/api/src/oauth-linuxdo.ts`) — 192-bit state, proper code exchange, avatar URL scheme validation. Clean.
- **OTA apply** (`apps/api/src/ota-apply.ts` + `packages/db/src/ota-repos.ts`) — content-addressed blobs by sha256 with re-hash on read (line 240), path allowlist (`isAllowedOtaPath`) enforced twice, whitelisted directories only, atomic swap with backup, `pnpm install --frozen-lockfile`. Design assumes Redis-write is a trust boundary (documented). Clean.
- **Sticker security** (`apps/api/src/sticker-security.ts`) — magic-byte sniff, mime-mismatch rejection, SVG forbidden, script-tag / eval / iframe pattern matching against latin1 view + extracted text runs, polyglot-tail detection past JPEG EOI / PNG IEND markers. Genuinely thorough. Clean.
- **Chatflow HTTP node** (`packages/core/src/chatflow/engine.ts:445-535`) — hostname allowlist, blocked-host reason check, `blockedResolvedReason()` for private ranges, per-hop re-check on manual redirect following. This is exactly the pattern the HF tools gateway should be using (Finding 1). Clean.
- **Admin authorization** (`apps/api/src/routes.ts`) — `requireUser` → `requireAdmin` → `requireSuperAdmin` chain properly enforced; per-endpoint `bot.owner_user_id !== user.id && !user.is_admin` gates on 8+ routes. Clean.
