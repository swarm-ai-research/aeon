## Confirmed findings

### 1. Shell injection via `${{ github.ref_name }}` in release workflow — **MEDIUM**

- **Location:** `.github/workflows/release-images.yml` (2 sites; see PVR for exact lines).
- **Class:** CWE-78 shell command injection inside a `run:` step that interpolates a template value directly into a shell script.
- **Attacker prerequisite:** push access to the repo (maintainer, collaborator, or compromised token with `contents: write`).
- **Blast radius:** high — the affected job holds `packages: write` + `id-token: write` and the ambient `GITHUB_TOKEN`. Successful exploitation would allow publishing arbitrary container images under `ghcr.io/guillaumemeyer/watermarks-remover:*` (including `:latest` and the harness matrix tags), i.e. a **downstream supply-chain compromise** for every consumer pulling from that GHCR namespace.
- **Fix shape (public because it's the standard pattern):** move the template value into a step-level `env:` block and reference it as a shell variable, plus optionally a paranoid semver ref-name whitelist as defense-in-depth. This is the same rewrite the GitHub Actions hardening docs, CodeQL `actions/actions-injection`, and Semgrep `run-shell-injection` all prescribe.
- **Disclosure channel:** PVR (drafted to `.pending-disclosure/guillaumemeyer-watermarks-remover-2026-08-22T164445Z-pvr.md`, pending operator submission). Exploit specifics and the tag payload are in the PVR body, not this local report, per SKILL step-7.

## Dropped semgrep candidates (5, all false-positive)

- `service/scripts/audit_website.py:24` (`use-defused-xml`) — stdlib ElementTree, but guarded by an explicit `b"<!DOCTYPE"`/`b"<!ENTITY"` byte-prefix rejection and stdlib ET has no external-entity resolution by default. Only bypass is a UTF-16-encoded sitemap yielding a billion-laughs DoS — which the maintainer's SECURITY.md scopes out ("parser crashes … that affect the host beyond normal process failure").
- `service/scripts/audit_website.py:346` (`httpsconnection-detected`) — used *inside* an SSRF-hardened `_open_pinned_connection` fetcher (IP-pinned to a pre-validated address while preserving TLS SNI and Host). Stdlib `HTTPSConnection` is the correct choice for that design.
- `service/scripts/image_meta.py:1424` (`dynamic-urllib-use-detected`) — `base_url` is `WATERMARKS_SYNTHID_SCORER_URL` (operator env var), and the scheme is validated to `http`/`https` immediately above the call. Not attacker-influenced.
- `service/scripts/image_meta.py:1486`, `:1585`, `:1664` and `service/scripts/text_detectors.py:223` (`dangerous-subprocess-use-tainted-env-args`, ×4) — all four are list-form `subprocess.run([...])` with `shell=False` (default). Argv elements bypass shell interpretation, so file paths containing shell metacharacters are literal string args, not commands.
