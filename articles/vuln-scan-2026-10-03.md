## Triage

Every semgrep candidate (23) was read in context against the surrounding 30–50 lines. **All 23 are false positives.** No TruffleHog or OSV hits. The repo's dependencies are at bleeding-edge pins (node 24.11, TypeScript 7.0.2, undici proxy agents) with no CVEs matching the OSV database.

### `express_open_redirect` × 2 (ERROR) — false positive

`apps/api/src/routes/admin-auth.ts:86,119` both pass user-controlled `returnTo` through `safeReturn()` (`packages/backend/src/admin/auth.ts:117-129`) before use. The wrapper strips `https?://` prefix, final-checks `/^\/admin(\/|\?|$)/`, and explicitly guards against protocol-relative `//`. Line 131's `reply.redirect(returnTo, 302)` uses a `returnTo` parsed out of a server-HMAC-signed state cookie whose inner value was sanitized before signing (line 111) — only key-compromise forgery can bypass.

### `node_password` × 1 (ERROR) — false positive

`packages/backend/src/admin/auth.ts:195`: `const PASSWORD_ADMIN = "admin@local"` — this is the reserved email identifier for the sole password-admin row, not a credential. The actual password check at `passwordLogin()` (line 198) requires `config.adminPassword` from env.

### `node_secret` × 1 (ERROR) — false positive

`packages/backend/src/operations/backup.ts:60`: `"aws4_request"` string literal is the AWS Signature V4 **standard scope suffix**, not a secret. The real `accessKey`/`secretKey` are passed as function args from `store()` config.

### `node_timing_attack` × 1 (WARNING) — false positive

`packages/backend/src/content/extract.ts:100`: `hash === row.content_hash` where `hash` is a non-secret SHA-256 of article `(title, bodyText, excerpt)` used for change-detection deduplication, not an auth token. No timing-attack impact.

### `regex_dos` × 12 (WARNING) — all false positive

All 12 patterns are either (a) fully anchored short-prefix matches (`^https?:\/\//`, `^\d+$`, `^[0-9a-f]{64}$`), (b) applied to bounded input (`body.subarray(0, 2048)`), or (c) non-nested alternations without overlapping character classes. None exhibit catastrophic backtracking:

## Why no finding survived — the defensive engineering

I did not stop at scanner triage. Independent review of the exposed attack surface:

- **SSRF guard (`packages/backend/src/lib/url.ts`)** is unusually complete. It blocks every RFC-reserved IPv4 range (loopback, private, link-local AND cloud metadata, carrier-grade NAT, documentation, 6to4-anycast, TEST-NET-1/2/3) and every corresponding IPv6 range (mapped `::ffff:/96`, compatible `::/96`, NAT64 `64:ff9b::/96` + local-use `64:ff9b:1::/48`, 6to4 `2002::/16` with embedded IPv4 re-check, Teredo `2001::/32`, documentation `2001:db8::/32`, discard `100::/64`, unique-local `fc00::/7`, link-local `fe80::/10`, site-local `fec0::/10`, multicast `ff00::/8`). It also blocks the `localhost`/`.localhost`/`.internal`/`metadata.google.internal` hostnames. The connect-time `guardedLookup` closes the DNS-rebinding window by re-checking the actual dialed address.

- **`guardedFetch` (`packages/backend/src/lib/http-fetch.ts`)** builds on this with manual redirect handling (so the SSRF guard runs per-hop), a response-size cap, a single DNS+redirect+body deadline, and credential-bearing redirects pinned to the original origin.

- **Admin auth (`packages/backend/src/admin/auth.ts`)** uses HMAC-signed session binding tied to the current `ADMIN_PASSWORD`/`FEISHU_LOGIN_APP_ID` so config rotation invalidates live sessions; timing-safe comparisons throughout; opaque session tokens stored as SHA-256; signed OAuth state cookie carrying a pre-sanitized `returnTo`.

- **Image proxy (`packages/backend/src/media/imgproxy.ts`)** is HMAC-signed with `IMG_PROXY_SIGN_SECRET` + expiry, timing-safe-compared, response CSP-sandboxed. Only server-crawled URLs can be signed; `guardedFetch` applies to the actual outbound.

- **Ingest route** rejects placeholder tokens (`changeme`, `test`, etc.) and tokens shorter than 16 chars before timing-safe-compare of the bearer header.

- **Public v1/agent routes** validate query shape with `strictQuery` + `enumParam`/`intParam` on every parameter.

- **File-serving `/contact/:file`** validates filename against `/^[\w.-]+\.(png|jpg|jpeg|webp)$/`, which rejects `/`, `\`, and leading-dot path-traversal attempts.
