## Confirmed findings

### 1. `oras.land/oras-go/v2 2.6.1` — four disclosed advisories (High/Moderate)

Direct dependency at `go.mod:85`, used by
`internal/llm/llamacpp/ociregistry/client.go` for Hugging Face / OCI
model pulls. All four advisories fixed in **v2.6.2**:

| Advisory | Severity |
|---|---|
| GHSA-fxhp-mv3v-67qp — hardlink relative-Linkname escapes extract dir | High |
| GHSA-m37j-52j7-pjw7 — symlink-chain bypass in `pushDir` tar extraction | High |
| GHSA-h7vf-4x9w-h99v — blind SSRF via `Link`-header pagination | Moderate |
| GO-2026-5880 — hardlink path traversal (aggregate) | — |

**Reachable code path:** rune's `FetchManifest` and `Pull` route through
`oras-go/v2/registry/remote`, the same package that carries the SSRF
fix. Rune does *not* use `file.Store` tar extraction directly (blobs are
downloaded via `Blobs().Fetch` and written by rune's own extractor), so
the two High-severity hardlink/symlink advisories are defence-in-depth
rather than an active exposure through rune's own call paths.

- **Channel:** public PR (already-public CVEs).
- **Draft:** `.pending-disclosure/unstablebuild-rune-2026-09-19T164400Z-deps.md`

### 2. `idepkg` tar extractor — symlink placement, zip-slip, decompression bomb

`internal/ide/idepkg/manager.go:1854-1913` (`untar`) does not apply the
zip-slip prefix guard, does not validate symlink `Linkname` targets, and
copies regular-file content with unbounded `io.Copy`. The same pattern
recurs at `internal/ide/ideupgrade/extract.go:101` (self-upgrade
extractor).

The manager's own signature check
(`m.trust.VerifyBundle`) is **skipped** for `gitpkg`-typed packages
(`internal/ide/idepkg/manager.go:756`), so any user who runs `rune
install github.com/<attacker>/<pkg>` is trusting the extractor to enforce
its own bounds. Composite exposure: symlink into `~/.ssh` via `Linkname
= ../../../../home/…`, arbitrary file write via `Name = ../../etc/…`,
disk-fill via a bomb.

- **Severity:** Medium (defence-in-depth; needs user to install a
  hostile git-URL package or a bypass of `VerifyBundle`).
- **CWEs:** CWE-22, CWE-59, CWE-409.
- **Channel:** PVR (unpatched code flaw).
- **Draft:** `.pending-disclosure/unstablebuild-rune-2026-09-19T164400Z-pvr.md`
