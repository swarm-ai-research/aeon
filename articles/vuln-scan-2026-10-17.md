## Semgrep candidates (3 → 0 confirmed)

### 1. `.github/workflows/ci.yml:12,13` — mutable action tag (WARNING)
`actions/checkout@v4` and `actions/setup-node@v4`. Both first-party GitHub actions. CI job already restricts `permissions: contents: read`. The pin recommendation would ratchet from a `v4` tag to a 40-char SHA — hygiene, not a vulnerability. **Discard.**

### 2. `deployment/computers/supervisor.Dockerfile:11` — missing USER (ERROR)
This Dockerfile builds a Playwright-based browser microservice sidecar. `oven/bun:1.3.14-alpine` defaults to root. The repo's own `SECURITY.md` explicitly carves this out: *"Keep the browser service isolated from the application host and private networks. Do not expose its port publicly."* The threat model already assumes network isolation; a `USER` directive is a defense-in-depth hardening recommendation, not a vulnerability class with a plausible attacker path. **Discard** (would raise it as a hardening note in a PVR only if paired with a real finding; not standalone).

## Code-level defenses reviewed (no findings)

- **SSRF** (`src/browser/security.ts`, `src/browser/transport.ts`): IPv4 reserved-range blocks are complete including CGNAT (100.64/10), link-local (169.254/16), TEST-NET-1/2/3, and multicast (≥224). IPv6 is restricted to the 2000::/3 global unicast range with explicit exclusions for 2001:0/23 (Teredo + reserved), 2001:db8/32 (documentation), 2002::/16 (6to4), 3fff::/20 (future-use), 2001:10/28 (ORCHID), 2001:20/28 (ORCHIDv2); IPv4-mapped and IPv4-compatible IPv6 are blocked implicitly by the regex gate. DNS is resolved once, then pinned via `lookup` override on the Node HTTP agent — defeats DNS rebinding. Redirects rejected before Playwright sees the Location header. Each resource is re-validated in `route.fulfill`; the final `page.url()` is validated again after navigation.
- **Slack identity binding** (`src/server/slack-channel.ts`): identifies only when `provider==='slack'` ∧ `tenant.id===config.slackTeam` ∧ `actor.kind==='human'` ∧ `actor.id ∈ config.slackUsers` (explicit allowlist). No display-name trust. Error paths mask SDK causes via `safeFailure()` to prevent credential leakage into logs.
- **Owner auth** (`src/server/app.ts`): host allowlist + `sec-fetch-site` cross-site rejection + strict JSON content-type + timing-safe owner-token compare. Fail-closed on no-ownerToken-with-external-binding at startup (`src/server/index.ts:21-27`).
- **Voice** (`src/server/voice.ts`): server-held `VOICE_API_KEY`, hardcoded `https://api.openai.com/v1/realtime/calls`, `redirect: 'error'`, SDP validated both directions (`v=0` + `m=audio` + ≤100 KB), provider call-ID regex-constrained, six-turn compute cap, 15-minute deadline, hangup on every failure path.
- **Computer gateway** (`src/server/computer-service.ts`): per-Dot HMAC-sha256 token (never the raw `COMPUTER_TOKEN`), Dot ID regex `/^[A-Za-z0-9][A-Za-z0-9_-]{0,63}$/`, namespace regex, endpoint allowlist (`container-name:4100` OR `127.0.0.1:supervisor-advertised-port`), redirect: error, 70s deadline, 4 MB response cap, upstream secrets redacted before parse, permission re-check every 50 ms during long actions (TOCTOU window on revocation ≤ 50 ms).
- **Page revisions** (`src/server/pages.ts`): all SQL parameterized, Space-scoped reads, cycle detection in parent reassignment, revision check with `BEGIN IMMEDIATE` + `UPDATE … WHERE revision=?` + `COMMIT/ROLLBACK`, reviewed-page retry-idempotency via `(threadId, toolCallId)` primary key with content-hash equivalence check.
- **Composio sessions** (`src/server/composio.ts`): toolkit allowlist stored on Dot, SHA-256 policy hash keys session reuse so a toolkit-set change invalidates a stale session instead of silently extending the grant.
- **CSP + headers** (`src/server/index.ts:103-110`): tight `default-src 'self'`, no `unsafe-inline` on scripts (only styles — React requirement), `frame-ancestors 'none'`, `base-uri 'self'`, `form-action 'self'`.
